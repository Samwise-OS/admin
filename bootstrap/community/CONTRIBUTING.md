# Contributing to Samwise-OS

Start with an issue describing the problem, expected behavior and observable acceptance.
Keep changes within that issue's scope. Use a short branch and pull request; explain
the outcome, evidence and any migration/recovery implications. Project documentation
defines the actual build/test commands.

Use the installed namespaced Matt Pocock engineering skills for specifications,
dependency-linked tickets, behavior-driven red/green implementation and separate
Standards/Spec review. Generated tickets skip incoming-request triage. Record real
tradeoffs in concise ADRs and keep the glossary focused on domain terms.

The solo-maintainer bootstrap requires passing CI and a PR trail with self-review.
It does not claim independent review. Projects add an independent reviewer when one
is available. Never place credentials, private vulnerability details or personal data
in public issues or logs.
